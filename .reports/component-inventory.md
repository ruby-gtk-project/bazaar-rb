# bazaar-rb component inventory

Survey only — no app code written in this step. Compares upstream
`io.github.kolunmi.Bazaar` (on `origin/main`, read with `git show
origin/main:<path>`, never checked out) against `lib/` on `ruby`.

## Scale

Upstream is a full Flatpak/Flathub app store client: ~155 `src/bz-*.{c,h}`
classes (most paired with a `src/bz-*.blp` template compiled into
`bazaar.gresource.xml`), plus ~28 `src/bz-*.txt` pure-data-model specs fed
through `src/gen_gobject.sh` to generate GObject boilerplate, plus app-level
files (`bz-application.c`, `bz-window.c`), workers/services, parsers, and a
`data/` tree (one GSettings schema, one `.desktop.in`, one `.metainfo.xml.in`,
icons) and a `po/` catalogue of 31 shipped languages (see `po/LINGUAS`) over
155 files in `po/POTFILES.in`.

`ruby` currently has 30 files under `lib/`. This is an early-stage port: most
of the 185 upstream units below have no corresponding `lib/*.rb` file yet.

## Known name mismatches (do not read these as "missing")

The table below matches by stripping `bz-` and converting dashes to
underscores, which misses a few files already ported under a different,
more idiomatic name:

| lib/*.rb (exists) | Ported from |
|---|---|
| `lib/flatpak_backend.rb` | `src/bz-flatpak-instance.c` / `.h` (the `Backend` implementation backed by Flatpak) |
| `lib/about_dialog.rb` | `bz_application_about_action` in `src/bz-application.c` (upstream has no standalone `bz-about-dialog.c`; the About dialog is built inline) |
| `lib/bazaar.rb` | entry point, requires `lib/bazaar/application.rb` ↔ `src/main.c` + `src/bz-application.c` |
| `lib/bazaar/application.rb` | `src/bz-application.c` / `.h` |
| `lib/bazaar/rb/version.rb` | gem version — no upstream equivalent |
| `lib/settings.rb` | `data/io.github.kolunmi.Bazaar.gschema.xml` (all 14 keys present) |
| `lib/shortcuts_dialog.rb` | `src/shortcuts-dialog.blp` (`Adw.ShortcutsDialog`, no `.c`) |
| `lib/state_info.rb` | `src/bz-state-info.txt` (codegen data-model spec) |

Treat all eight as **present**, not missing, even though the mechanical
name-match below marks some of their upstream sources as unmatched.

## GSettings

`data/io.github.kolunmi.Bazaar.gschema.xml` has 14 keys (`auto-update`,
`auto-update-notifications`, `check-for-ubuntu`, `force-adwaita-icons`,
`global-progress-bar-theme`, `hide-eol`, `last-refresh-time`,
`last-stale-notification`, `last-update-check`, `show-only-flathub`,
`show-only-foss`, `show-only-verified`, `show-permission-banner`,
`update-check-hour-offset`, `window-dimensions`). `lib/settings.rb` already
backs all 14 with a JSON file in place of a compiled schema — present, keys
verified by inspection.

There are four more GSettings-shaped schemas compiled as plain GVariant/XML
resources rather than app-prefs schemas — `internal-config-schema.xml`,
`main-config-schema.xml`, `blocklist-schema.xml`, `curated-config-schema.xml`,
`pride-flag-config-schema.xml`, `article-list-schema.xml` — these back the
flathub curated-content / blocklist / pride-flag YAML config layer, not user
preferences. No `lib/*.rb` covers that config layer yet (see
`bz-root-curated-config`, `bz-root-blocklist`, `bz-pride-flag-config` rows
below).

## Unit inventory

unit being ported — run that per-file scan when a specific unit is picked up.

# bazaar-rb component inventory

Generated by scanning `origin/main` (upstream bazaar, C/blueprint) and comparing
against `lib/` on `ruby`. Upstream has no single `.ui`/`.blp` per class in all
cases — most C classes pair with a `.blp` template; some are pure data/model
classes generated from a `.txt` spec via `src/gen_gobject.sh` and have no widget
tree at all. Counts below are **unit counts** (one upstream class = one row),
not widget instance counts — see `.claude/skills/component-identification` for
the full per-widget scan, which is the next-level task once units are assigned.

**Totals: 185 upstream units, 25 already have a corresponding `lib/*.rb` file by name, 160 do not.**

Note: a handful of existing `lib/*.rb` files were ported under a different name
than their upstream basename and so are *not* auto-matched by this table — see
"Known name mismatches" below. Treat those as present, not missing.
